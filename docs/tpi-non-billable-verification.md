## ผลที่ทำแล้ว

- กลุ่ม 3 สีมารูนทั้งหน้าจัดการรหัสงานและลงกะ พร้อมปุ่มเพิ่มงานไม่ตั้งเบิกและฟอร์มกำหนดตำแหน่ง/เรท/กะ
- เลือกงานอ้างอิงหรือระบุตำแหน่ง/เรทเอง มีผู้รับต้นทุนและเหตุผล แก้เรทเฉพาะรายการได้
- เก็บสถานะไม่ตั้งเบิก ตำแหน่ง งานอ้างอิง เรทอ้างอิง เรทจริง และประวัติการเปลี่ยนแปลง
- รวมค่าแรงในยอดจ่ายและกระบวนการประกันสังคมเดิม แยกออกจากใบตั้งเบิกทั้งแบบรหัสงานและรายบุคคล
- แสดงการเปลี่ยนแปลงในพื้นที่ตรวจสอบ SuperUser ของ Dashboard มีการตรวจสิทธิ์ที่ฐานข้อมูล
- Excel ภายในแยกค่าแรงก่อนปรับยอด ค่าแรงส่วนที่ตั้งเบิก ค่าแรงไม่ตั้งเบิก และวันทำงานไม่ตั้งเบิก รายละเอียดรายคนมีเหตุผล ผู้รับต้นทุน และเลขรายการ
- งานที่อนุมัติงวดแล้วแก้รายการไม่ตั้งเบิกไม่ได้ ต้องเปิดงวดก่อน

## หลักฐานทดสอบ

- ตรวจ lint ของส่วนประกอบใหม่ทั้ง 4 ไฟล์ผ่าน
- Build ผ่าน มีคำเตือนขนาด bundle และการ import XLSX เดิมของโครงการ
- ชุดทดสอบ Node ผ่าน 80 รายการ รวมของเดิม 72 และเคสใหม่ 8
- รัน migration ฉบับเต็มกับ PostgreSQL ในเครื่องที่แยกจากข้อมูลจริง แล้วผ่านชุดทดสอบฐานข้อมูลแบบ transaction/rollback
- ฐานข้อมูล: ค่าแรง 357 บาท, การบันทึกซ้ำไม่แจ้งซ้ำ, แก้เรทเฉพาะรายการ, คงค่าแรง/ตำแหน่งย้อนหลัง, หักชั่วโมงครั้งเดียว, จำกัดกะเช้า, ปฏิเสธงาน/พนักงานข้ามโรงงาน, จัดล่วงหน้าเก็บข้อมูลครบ, ล็อกงวดอนุมัติ, เก็บประวัติลบ, Admin อ่านประวัติ SuperUser ไม่ได้ และ SuperUser อ่านได้
- Browser: ใช้ข้อมูลจำลอง ตรวจกลุ่ม 3 วางพนักงานลงกะเช้าและเปิดช่องแก้เรท 357 บาทได้ ตรวจฟอร์มจัดการรหัสงานและตัวกรองสีมารูน
- Browser: ชุดจำลองแยกที่ปิดการเรียกข้อมูลจริง ตรวจสลับจาก TPI เป็นตราเพชรแล้วเปิด URL งาน TPI ถูกปฏิเสธ เปิดหน้ากรอกค่าจ้างตราเพชรและเลือกคนงานแล้วไม่มีช่องงานไม่ตั้งเบิก
- ตรวจโค้ดหน้ากรอกค่าจ้าง สลิป หน้าสลิปพนักงาน สรุปพนักงาน ลงกะ ตัวคำนวณตราเพชร และส่วนสร้างเอกสารสลิป รวม 9 ไฟล์ เทียบฐานเริ่มต้นแล้วไม่เปลี่ยน
- ตรวจโครงสร้างโค้ดส่งออก Excel ส่วนกลาง: เส้นทางตราเพชรเดิม 10 ส่วนยังเหมือนฐานเดิม การคำนวณใหม่ถูกจำกัดในเงื่อนไข TPI
- TypeScript ทั้งโครงการยังไม่ผ่านจากข้อผิดพลาด 735 รายการ เทียบฐานก่อนแก้ที่มี 744 รายการแล้วไม่พบประเภทข้อผิดพลาดใหม่ในไฟล์ที่แก้ ไม่ได้อ้างว่า typecheck ผ่าน

## วิธีทดสอบซ้ำ

ทดสอบฟังก์ชัน:

```sh
node --experimental-strip-types --test tests/tpi/*.test.mjs tests/payroll/*.test.mjs
npm run build
```

ทดสอบฐานข้อมูล: ใช้ฐาน PostgreSQL ว่างที่ทิ้งได้ในเครื่องเท่านั้น ไฟล์ non-billable-fixture.sql สร้าง schema และข้อมูลจำลองก่อนรัน migration และชุดตรวจ ห้ามรัน fixture กับฐานข้อมูลจริง

```sh
psql -h /tmp -p 55439 -d payroll_tpi_test -v ON_ERROR_STOP=1 -f tests/tpi/non-billable-fixture.sql
```

ต้องสร้างฐานว่างใหม่สำหรับการรัน fixture แต่ละครั้ง ส่วน non-billable-database.sql rollback ข้อมูลทดสอบท้ายไฟล์

ทดสอบหน้าจอจำลองผ่าน Vite:

- /preview/tpi-shifts สำหรับการลงกะ
- /tests/tpi/non-billable-browser.html สำหรับฟอร์มรหัสงาน การสลับโรงงาน และค่าจ้างตราเพชร ข้อมูลทุกคำขอในหน้านี้เป็นข้อมูลจำลอง ไม่ใช้ข้อมูลจริง

## ขอบเขตการตรวจและก่อนใช้จริง

ยังไม่ push, deploy หรือเปลี่ยนฐานข้อมูลจริง ต้องนำ migration 20261020054636_tpi_non_billable_work.sql ขึ้นก่อนเผยแพร่โค้ดฟีเจอร์ และตรวจด้วยบัญชี Admin/SuperUser ในสภาพแวดล้อมทดสอบที่เชื่อมฐานข้อมูลครบก่อนเปิดใช้งานจริง

การทดสอบ browser ใช้ข้อมูลจำลอง ส่วนการทดสอบ SQL ใช้ฐานข้อมูลในเครื่อง ไม่ได้ทดสอบการบันทึกจาก browser ถึง Supabase จริงใน session เดียว และไม่ได้ส่งออกสลิป/Excel ของข้อมูลพนักงานจริงเพื่อเปรียบเทียบ ไฟล์และเส้นทางตราเพชรที่เกี่ยวข้องถูกตรวจเทียบโค้ดกับฐานเดิม และชุดคำนวณเดิมผ่าน

ยังไม่ได้สร้าง master record ในฐานข้อมูลจริง ผู้ใช้เพิ่มงานและกำหนดตำแหน่งผ่านปุ่มเพิ่มงานไม่ตั้งเบิก

## ปรับหน้ารหัสงานและข้อความตามคำขอเพิ่มเติม

- คืนคอลัมน์เดิมทั้งหมด 15 คอลัมน์ ได้แก่ รหัสงาน แผนก รายละเอียด ประเภท กลุ่มงาน ยอดเต็ม ตั้งเบิกปกติ ตั้งเบิกฝีมือ จ่ายปกติ จ่ายฝีมือ ส่วนต่างปกติ ส่วนต่างฝีมือ วันหมดอายุ สถานะ และจัดการ
- แสดงหัวตารางสองชั้นเฉพาะกลุ่มตัวเลข แต่ข้อมูลแต่ละอัตรายังคงเป็นคนละคอลัมน์ รวมเปอร์เซ็นต์ส่วนต่างและหมายเหตุเดิมครบ
- ลดระยะช่องว่าง จำกัดความกว้างหน้า และจัดข้อความยาวให้ขึ้นบรรทัด โดยไม่ตัดข้อความหรือซ่อนคอลัมน์
- ตัดชื่อโรงงานและชื่อ หจก. ออกจากป้ายงานพิเศษที่ซ้ำ เก็บข้อมูลผู้รับต้นทุนในช่องและประวัติที่ใช้ตรวจสอบ
- ตรวจหน้าจอจำลองพร้อมตัวอย่างเรทตั้งเบิก 457/492 จ่าย 357/377 และส่วนต่าง 100/115 แล้ว เห็นกลุ่มงานและอัตราครบ
- Build และชุดทดสอบเดิมผ่านก่อนปรับรอบนี้ โดยรอบแก้ตารางนี้ตรวจ lint และ build ซ้ำ พร้อมตรวจหน้าจอจริงในชุดข้อมูลจำลอง
- ยังไม่ push หรือ deploy และไม่เปลี่ยนข้อมูลจริง

### แก้รายละเอียดขอบตาราง แนวตัวเลข และปุ่ม

- ใช้กรอบที่ตัดพื้นหลังตามมุมโค้งและแยกเส้นตาราง เพื่อให้มุมไม่แหว่ง
- เพิ่มพื้นที่ยอดเต็มและห้ามตัดบรรทัดจำนวน/หน่วย
- จัดหัวอัตราปกติ/ฝีมือและข้อมูลตัวเลขให้อยู่กึ่งกลางคอลัมน์เดียวกันทั้งหกคอลัมน์
- ตัวกรองทุกประเภท กลุ่ม 1 กลุ่ม 2 และกลุ่ม 3 อยู่ในกรอบเดียว คั่นด้วย | และเพิ่มระยะห่าง
- ย้ายปุ่มเพิ่มงานไม่ตั้งเบิกไปบริเวณเพิ่มรหัสงานด้านบน เอาชื่อโฟร์แมนและตัวเลขค่าแรงออกจากปุ่ม และเปิดฟอร์มเปล่าประเภทไม่ตั้งเบิก
- ตรวจหน้าจอจำลองครบทั้งตารางและการเปิดฟอร์ม ไม่มีการบันทึกข้อมูลจริง

## ติดตั้งฐานข้อมูลจริงตามการอนุญาตของผู้ใช้ 20 ตุลาคม 2026

- ผู้ใช้อนุญาตให้ติดตั้ง migration กับฐานข้อมูลจริงหลังพบว่าหน้าเพิ่มงานบันทึกไม่ได้
- ติดตั้ง `tpi_non_billable_work` ในโครงการ Payroll สำเร็จ และสั่ง reload schema cache ของ Data API
- ตรวจคอลัมน์ใหม่รหัสงาน 4 ช่อง รายการลงกะ 7 ช่อง trigger 3 ตัว และ RLS ของ audit ครบ
- ทดสอบ INSERT ด้วย role authenticated และสิทธิ์ Admin โรงงาน TPI บันทึกงานไม่ตั้งเบิก 357 บาท กะเช้าได้ และ trigger บังคับเรทตั้งเบิกทั้งสามช่องเป็น 0
- ข้อมูลทดสอบทั้งหมดอยู่ใน transaction แล้ว ROLLBACK ไม่มีรหัส VERIFY-NB เหลือ
- ทดสอบฐานข้อมูลปฏิเสธงานไม่ตั้งเบิกที่ผูกกับโรงงานตราเพชร โดย rollback ทั้งหมด
- เทียบ fingerprint คอลัมน์ ฟังก์ชัน และ policies ของส่วน public ที่ไม่ขึ้นต้น tpi_ ก่อนและหลังติดตั้งเหมือนกันทั้งหมด
- Security advisor ก่อนและหลังยังเป็นคำเตือนเดิม ไม่มีรายการเพิ่มจาก migration นี้
- การทดสอบครั้งนี้ยืนยันการบันทึกที่ระดับฐานข้อมูลและสิทธิ์ผู้ใช้ ยังไม่ได้กดบันทึกผ่าน browser ด้วย session ของผู้ใช้จริง
- รอบนี้ติดตั้งเฉพาะฐานข้อมูล ไม่ได้ push หรือ deploy โค้ดเว็บ และไม่ได้สร้างรหัสโฟร์แมนจริงแทนผู้ใช้
