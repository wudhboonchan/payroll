# แผนงาน TPI: ลงกะที่จ่ายค่าแรงแต่ไม่ตั้งเบิก

สถานะ: ได้รับไฟเขียวและสร้างโค้ดใน branch codex/tpi-non-billable-work แล้ว ทดสอบในเครื่อง ยังไม่เปลี่ยนฐานข้อมูลจริง ไม่ push และไม่ deploy

## ข้อบังคับ: ห้ามกระทบโรงงานตราเพชร

- ขอบเขตนี้ครอบคลุมทุกส่วนของตราเพชร ไม่จำกัดสลิปหรือ Excel ผู้ใช้ยืนยันว่าเคยเกิดปัญหาฟีเจอร์ข้ามโรงงานแล้ว จึงถือเป็นเงื่อนไขหยุดการนำขึ้นใช้งานหากยังพิสูจน์การแยกไม่ได้
- หน้ากรอกค่าจ้างตราเพชรต้องไม่มีตัวเลือก ช่องกรอก กลุ่มงาน ป้าย ยอดแยก หรือพฤติกรรมใหม่จากฟีเจอร์นี้ แม้เข้า URL โดยตรงหรือสลับมาจาก TPI
- ครอบคลุมหน้าจัดการรหัสงาน ลงกะ กรอกค่าจ้าง ประวัติ สรุป รายงาน สลิป Excel การแจ้งเตือน และข้อมูลสรุปของผู้บริหารที่เกี่ยวกับตราเพชร รวมเส้นทางอื่นที่พบจากการตรวจระบบ
- ตรวจทั้งการแสดงผล การอ่าน/บันทึกข้อมูล การคำนวณ สิทธิ์ ตัวกรอง cache และสถานะค้างในหน้าจอ การซ่อน UI เพียงอย่างเดียวไม่ถือว่าแยกสำเร็จ
- ตรวจเส้นทางสร้าง/แก้ไขให้ปฏิเสธรายการหรือคุณสมบัติใหม่เมื่อปลายทางเป็นตราเพชร รวมการอ้างรหัสงานข้ามโรงงาน โดยใช้ข้อมูลโรงงานที่ตรวจสอบได้ฝั่งจัดเก็บ
- ก่อนเริ่มแก้ ทำรายการจุดใช้ร่วมและเส้นทางตราเพชรที่ต้องตรวจ หลังแก้ต้องทดสอบตราเพชรโดยตรงและสลับ TPI ไปตราเพชร รวมโหลดใหม่ บันทึก เปิดย้อนหลัง และส่งออก โดยใช้ข้อมูลทดสอบที่แยกจากข้อมูลจริง
- ฟีเจอร์และพฤติกรรมใหม่ทั้งหมดใช้เฉพาะ TPI ต้องตรวจโรงงานจากข้อมูลและบริบทที่เชื่อถือได้ ไม่ใช้แค่การซ่อนหน้าจอ
- ห้ามเปลี่ยนข้อมูล การคำนวณ รูปแบบ และรายการที่แสดงบนสลิปหรือ Excel ของตราเพชร รวมถึงชื่อคอลัมน์ ลำดับ สูตร ยอดรวม และจำนวนรายการ
- เก็บผลอ้างอิงสลิปและ Excel ตราเพชรจากข้อมูลชุดเดียวกันก่อนแก้ เพื่อเปรียบเทียบหลังแก้ทั้งข้อมูลและรูปแบบ โดยไม่แก้ข้อมูลจริงเพื่อทดสอบ
- ตรวจการสลับโรงงานด้วย เพื่อป้องกันตัวเลือก สถานะ ตัวกรอง หรือข้อมูลที่ค้างจาก TPI ไปมีผลกับตราเพชร
- ตรวจจุดใช้ร่วมกัน โดยเฉพาะหน้าสลิป ตัวคำนวณค่าแรง และตัวส่งออก Excel ก่อนแก้ หากต้องแก้ส่วนร่วม ให้แยกเส้นทาง TPI ชัดเจนและมีการทดสอบยืนยันผลเดิมของตราเพชร
- การเปลี่ยนโครงสร้างข้อมูลต้องรองรับข้อมูลเดิม ห้ามปรับข้อมูลตราเพชรย้อนหลังหรือเปลี่ยนค่าเริ่มต้นที่ทำให้พฤติกรรมตราเพชรเปลี่ยน
- ไม่ผ่านเกณฑ์ตรวจรับหากพบความต่างบนสลิปหรือ Excel ตราเพชรที่เกิดจากงานรอบนี้ ต้องแก้ให้ผลเดิมก่อนนำขึ้นใช้งาน

## เป้าหมาย

เพิ่มกลุ่ม 3 “งานไม่ตั้งเบิก” เฉพาะ TPI ใช้การสร้างรหัสงานและวางพนักงานลงกะแบบเดิม รวมค่าแรงในยอดจ่าย แต่ไม่รวมรายการในเอกสารตั้งเบิกโรงงาน และตรวจสอบย้อนหลังได้

## ข้อสรุปที่ใช้ในรุ่นนี้

- งานโฟร์แมน 357 บาทต่อวัน กะเช้าวันละหนึ่งกะ หจก.รับต้นทุนเอง ไม่ตั้งเบิก TPI
- มีปุ่มเพิ่มงานไม่ตั้งเบิกอยู่กับปุ่มเพิ่มรหัสงานด้านบน ผู้ใช้ระบุรหัสงานและตำแหน่งเอง ไม่ผูกชื่อปุ่มกับโฟร์แมนหรือยอดเงิน
- ใช้สิทธิ์จัดการ TPI เดิม และแจ้ง SuperUser หลังบันทึก ไม่เพิ่มขั้นตอนอนุมัติก่อนจ่าย
- ประกันสังคมและค่าแรงใช้กระบวนการเดิม งานไม่ตั้งเบิกที่จัดล่วงหน้าต้องยืนยันเข้างานก่อนนับค่าแรง
- งานกลุ่ม 3 อื่นตั้งตำแหน่ง เรท เหตุผล ผู้รับต้นทุน และตัวเลือกกะเช้าได้
- ไม่รองรับ OT ที่มีสถานะตั้งเบิกต่างจากกะหลักในรายการเดียว โดยปฏิเสธเพื่อป้องกันยอดผิด

## ประเด็นสำหรับเคสเพิ่มเติมในอนาคต

- ไม่ตั้งเบิกเฉพาะรายการงาน/กะ ไม่ใช่สถานะถาวรของพนักงาน ใช่หรือไม่
- ใครรับต้นทุน และต้องแยกรายงานตามหน่วยงานหรือโครงการหรือไม่
- ใครมีสิทธิ์สร้างงาน ระบุเรท และแก้เรท
- SuperUser รับทราบหลังบันทึก หรือจำเป็นต้องอนุมัติก่อนจ่าย
- กติกาครึ่งกะ ชั่วโมงไม่เต็ม OT วันหยุด ค่ากะ และสวัสดิการ ใช้กติกาใด
- รายการ OT ที่อ้างอิงงานอื่น อาจมีสถานะตั้งเบิกต่างจากกะหลักได้หรือไม่
- ใช้โครงสร้างตำแหน่ง/เรทเดิมอย่างไร รวมถึงเรทฝีมือที่ผูกกับงานประจำ

## ลำดับการทำงานเมื่อได้รับไฟเขียว

### 1. ตรวจเส้นทางและออกแบบข้อมูล

- ตามข้อมูลตั้งแต่รหัสงาน ลงกะ บันทึก คำนวณจ่าย ตั้งเบิก รายงาน และหน้าตรวจของ SuperUser
- แยกประเภทแสดงผลกลุ่ม 3 ออกจากสถานะตั้งเบิกที่ชัดเจน
- เก็บสถานะตั้งเบิก ตำแหน่ง/งานอ้างอิง เรทอ้างอิง เรทที่ใช้ เหตุผล ผู้รับต้นทุน ผู้บันทึกและเวลา ไว้กับรายการให้ตรวจย้อนหลังได้
- ข้อมูลเดิมต้องคำนวณได้เหมือนเดิม กำหนดแนวทางข้อมูลย้อนหลังอย่างชัดเจนก่อนเปลี่ยนโครงสร้าง
- ตรวจสิทธิ์และข้อจำกัดฝั่งจัดเก็บ ไม่พึ่งการซ่อนปุ่มเพียงอย่างเดียว

### 2. จัดการรหัสงานและลงกะ

- เพิ่มกลุ่ม 3 เฉพาะ TPI ในหน้าเดิม พร้อมป้าย “ไม่ตั้งเบิก”
- เลือกอ้างอิงงาน/ตำแหน่งเดิมเพื่อดึงเรท หรือกรอกเองตามสิทธิ์ พร้อมเหตุผล
- ดินสอแก้เรทมีผลเฉพาะรายการ ไม่แก้ต้นฉบับ และเก็บประวัติ
- การเลือกงานอ้างอิงไม่เพิ่มยอดจัดคนให้กับงานต้นฉบับ
- ตรวจลงกะซ้ำ การเปลี่ยนคน/งาน การลบรายการ และการแก้ย้อนหลัง
- รหัสงานที่ถูกใช้งานแล้วต้องปิดใช้ได้โดยไม่ทำลายประวัติ

### 3. คำนวณและแยกยอด

- ค่าแรงรายการใหม่เข้ายอดจ่ายคนงานตามกติกาที่ตกลง
- ตัดออกจากการตั้งเบิกก่อนรวมยอด จำนวนกะ จำนวนคน และจัดกลุ่มเอกสาร ไม่ใช่กรองตอนส่งออกอย่างเดียว
- งานไม่ตั้งเบิกไม่เพิ่มเป้าหมายหรือยอดขาดของงานปกติ
- ตรวจ OT แยกจากกะหลักหากระบบรองรับการอ้างอิงคนละงาน
- หากมีการแก้ยอดรวมค่าแรงรายงวด ต้องแสดงส่วนปรับแยกหรือกำหนดการจัดสรรที่ตรวจสอบได้ ห้ามกระจายเข้ายอดตั้งเบิกโดยไม่มีที่มา

### 4. SuperUser และประวัติ

- แจ้งหลังบันทึกสำเร็จแม้เรทไม่เปลี่ยน รวมการ override ไว้ในการแจ้งเดียว
- มีลิงก์หรือเลขรายการให้เปิดตรวจคนงาน วันที่ กะ เรท เหตุผล และผู้รับต้นทุน
- บันทึกข้อมูลกับเหตุการณ์ตรวจสอบอย่างสอดคล้องกัน จัดการบันทึกล้มเหลวหรือส่งซ้ำโดยไม่แจ้งซ้ำ
- การแก้หรือลบรายการที่แจ้งแล้วต้องมีประวัติ ไม่ทิ้งการแจ้งที่อ้างยอดเก่าราวกับยังเป็นยอดปัจจุบัน

### 5. Excel และรายงาน

- รายงานภายในเพิ่มค่าแรงที่ต้องจ่าย ค่าแรงส่วนที่ตั้งเบิก และค่าแรงไม่ตั้งเบิก พร้อมยอดรวม
- ใช้ฐานค่าแรงเดียวกันในการกระทบยอด ไม่เทียบยอดจ่ายสุทธิกับยอดใบตั้งเบิกทั้งหมด เพราะอาจมีเรทตั้งเบิกและค่าบริการต่างจากค่าแรง
- รายละเอียดมีวันที่ กะ งานพิเศษ งาน/ตำแหน่งอ้างอิง เรทเดิมและเรทจริง เหตุผล ผู้รับต้นทุน และเลขรายการ
- ให้ข้อความระบุสถานะชัดเจน สีเป็นเพียงตัวช่วย
- เอกสารส่ง TPI ไม่แสดงรายการภายในที่ไม่ตั้งเบิก

## เกณฑ์ตรวจรับ

- เคสกะเช้า 357 บาท: ยอดค่าแรงพนักงานเพิ่ม 357 ยอดตั้งเบิกไม่เพิ่ม และยอดไม่ตั้งเบิกแสดง 357
- คนเดียวทำงานตั้งเบิกได้และไม่ได้ต่างกะกัน ระบบแยกถูกและไม่ตัดสิทธิ์ทั้งคน
- อ้างอิงตำแหน่งเดิมแล้วดึงเรทถูก รวมกรณีเรทฝีมือ แก้เรทไม่กระทบงานหรือคนอื่น
- ครึ่งกะ OT วันหยุด และชั่วโมงไม่เต็มเป็นไปตามคำตอบที่ยืนยัน
- ข้อมูลใหม่ผ่านบันทึกและโหลดใหม่ได้ครบ ไม่หายระหว่างหน้าจอ
- แก้เรทต้นฉบับหรือปิดใช้รหัสงานแล้วข้อมูลย้อนหลังไม่เปลี่ยน
- ไม่เพิ่มยอดครบคนของงานอ้างอิง และยังตรวจงานซ้ำตามกติกาเดิม
- ผู้ไม่มีสิทธิ์ทำรายการไม่ได้ รวมเส้นทางบันทึกโดยตรง
- SuperUser เห็นรายการหลังบันทึก ไม่มีรายการซ้ำเมื่อบันทึกซ้ำหรือโหลดใหม่
- รายงานภายในกระทบยอดได้ เอกสารตั้งเบิกไม่มียอด/จำนวนคน/กะจากรายการไม่ตั้งเบิก
- งาน TPI เดิมและโรงงานอื่นได้ผลเดิม
- รันชุดตรวจเดิมที่เกี่ยวข้อง เพิ่มการทดสอบการคำนวณ/กรองยอด/บันทึกที่สำคัญ ตรวจ build และลองเส้นทางหน้าจอถึง Excel
